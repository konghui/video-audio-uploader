## 1. 概念与流程

服务把一个视频链接处理成如下流水线,页面通过 WebSocket 实时显示每一步:

```
粘贴链接 → ① 解析(校验支持性/取标题) → ② 下载 + 抽取音频转码
        → ③ 登录百度 + 创建目录 + 上传 → ④ 清理本地临时文件 → 完成
```

- 下载与转码由 `yt-dlp -x --audio-format <格式> --audio-quality 0` 完成(ffmpeg 内部调用)。
- 上传由 `BaiduPCS-Go`(先用 BDUSS+STOKEN 登录,再 mkdir 目标目录,再 upload)完成。
- 无数据库:所有状态来自 `config.yaml`,进度与会话存内存。
- 单用户单任务:同一时刻只处理一个任务,忙碌时新提交返回「忙碌中」。

## 2. 部署方式一:Docker / Podman(推荐)

镜像内置了全部运行依赖:`node`、`yt-dlp`、`ffmpeg`、`deno`(YouTube 需要)、`BaiduPCS-Go`(按 CPU 架构自动选 amd64 / arm64)。

### 2.1 步骤

```bash
# 克隆仓库
git clone https://github.com/konghui/video-audio-uploader
cd video-audio-uploader

# 准备配置
cp config.example.yaml config.yaml
# 编辑 config.yaml:改 sessionSecret、auth 账号密码、baidu.bduss / baidu.stoken、targetDir
vim config.yaml

# 创建挂载目录
mkdir -p data/tmp data/baidupcs

# 构建并启动
docker compose up -d          # 或:podman compose up -d

# 查看日志(应看到 "Server on :8080")
docker compose logs -f
```

浏览器打开 http://localhost:8080。

### 2.2 `docker-compose.yml` 挂载说明

| 挂载 | 用途 |
|------|------|
| `./config.yaml → /config/config.yaml` (只读) | 配置文件 |
| `./data/tmp → /data/tmp` | 下载/转码临时目录 |
| `./data/baidupcs → /root/.config/BaiduPCS-Go` | BaiduPCS-Go 登录态持久化(重启不丢) |
| 端口 `8080:8080` | Web 服务 |

### 2.3 Podman on macOS(Apple Silicon)注意

- 需先 `podman machine init && podman machine start`。
- 镜像会自动选 `arm64` 的 BaiduPCS-Go/deno,可正常执行。
- ⚠️ **容器 VM 到百度的上传带宽可能不稳定**,大文件(数 MB 以上)上传可能很慢甚至反复重试;小文件正常。这是网络环境问题,不是程序缺陷。生产环境建议部署在网络稳定的 Linux 主机。

## 3. 部署方式二:本地直接运行

适合开发或已装好依赖的机器。

### 3.1 前置依赖

- Node.js 20+(建议 22+)
- `yt-dlp`(`pip install yt-dlp` 或下载二进制)
- `ffmpeg`
- `deno`(仅 YouTube 需要:`curl -fsSL https://deno.land/install.sh | sh`)
- `BaiduPCS-Go` v4.0.2+(从 https://github.com/qjfoidnh/BaiduPCS-Go/releases 下载)

### 3.2 运行

```bash
npm install
npm run build                     # 后端 → dist/
cd web && npm install && npm run build && cd ..   # 前端 → web/dist/

cp config.example.yaml config.yaml
# 本地运行时把 paths.ytdlp / paths.ffmpeg / cloud.baidu.binary 改成本机命令名或绝对路径
# tempDir 改成本机可写目录,如 /tmp/audio

CONFIG_PATH=config.yaml node dist/index.js
```

### 3.3 前端热更新开发

```bash
# 终端 A:后端
CONFIG_PATH=config.yaml node dist/index.js
# 终端 B:前端(Vite 代理 /api 与 /ws 到 :8080)
cd web && npm run dev
```

## 4. 配置文件详解

```yaml
server:
  port: 8080                    # 监听端口
  sessionSecret: "..."          # 签名 cookie 密钥,务必改成随机串
auth:
  username: "admin"             # 登录用户名
  password: "..."               # 登录密码
paths:
  tempDir: "/data/tmp"          # 临时目录(下载/转码,上传后清理)
  ytdlp: "yt-dlp"               # yt-dlp 路径或命令名
  ffmpeg: "ffmpeg"              # ffmpeg 路径或命令名(裸命令名则从 PATH 找)
audio:
  format: "mp3"                 # 默认音频格式(界面可覆盖)
  quality: "0"                  # yt-dlp 音质,0 = 最高 VBR
cloud:
  provider: "baidu"             # 云盘类型(目前仅 baidu)
  baidu:
    binary: "BaiduPCS-Go"       # BaiduPCS-Go 路径或命令名
    bduss: "..."                # 百度 BDUSS(cookie)
    stoken: "..."               # 百度 STOKEN(cookie)—— 上传必需
    ptoken: "..."               # 可选,某些账号需要
    targetDir: "/小爱音乐"       # 网盘目标目录(不存在会自动创建)
```

> 启动时会做**预检**:配置字段完整性 + `yt-dlp`/`ffmpeg`/`BaiduPCS-Go` 是否可执行,缺失则报错退出。
> 若 `password` 或 `sessionSecret` 仍是 `change-me`,启动会打印告警。

## 5. 获取百度 BDUSS 与 STOKEN

1. 浏览器登录 https://pan.baidu.com
2. `F12` 打开开发者工具 → `Application`/应用 → 左侧 `Cookies` → 选 `https://pan.baidu.com`
3. 找到并复制这两个 cookie 的**值**:
   - **`BDUSS`**(很长一串)
   - **`STOKEN`**
4. 分别填入 `config.yaml` 的 `cloud.baidu.bduss` 和 `cloud.baidu.stoken`

要点:
- **只填 BDUSS 会导致上传失败**(报「请重新登录」),STOKEN 必填。
- 凭证会过期,过期后重新从浏览器复制即可。
- 首次上传若目标目录不存在,程序会自动 `mkdir`。

## 6. Web 界面使用

1. **登录页**:输入 `config.yaml` 里的用户名/密码,点「进入」。
2. **主页面**:
   - 顶部输入框粘贴视频链接;右侧下拉选择输出格式(默认 mp3)。
   - 点「校验」→ 显示 `✅ 支持:<标题> (<时长>)` 或 `❌ 不支持:<原因>`。
   - 校验通过后「开始提取并上传」按钮可点。
   - 提交后出现进度卡片:阶段(解析/下载转码/上传网盘/清理/完成)+ 百分比 + 实时日志。
   - 完成显示「全部完成 🎉」,失败显示「任务失败」+ 错误信息。
3. **云盘目录卡片**(页面下方):
   - 显示 `targetDir` 里的文件:名称 / 大小 / 修改时间。
   - 每行「下载」= 从网盘拉取并保存到你本机;「删除」= 从网盘删除。
   - 「刷新」手动刷新;任务完成后自动刷新。
4. 刷新页面会自动恢复当前/最近一次任务的状态。

## 7. 支持的视频网站与音频格式

### 视频网站

基于 `yt-dlp`,**自动支持其能识别的所有网站**(Bilibili、YouTube、优酷等上千站点),无需为每个网站单独配置。粘贴链接后由默认 `YtDlpSource` 处理。

### 音频格式(界面下拉可选)

| 值 | 说明 |
|----|------|
| `mp3` | 默认,兼容性最好 |
| `m4a` | AAC in MP4,体积/质量均衡 |
| `opus` | 高压缩高质量 |
| `aac` | |
| `flac` | 无损 |
| `wav` | 无损未压缩 |
| `vorbis` | Ogg Vorbis |
| `alac` | Apple 无损 |
| `best` | yt-dlp 选原始最佳(不强制转码容器) |

统一使用 `--audio-quality 0`(最高质量)。

## 8. HTTP API 参考

所有 `/api/*`(除 `/api/login`)与 `/ws` 均需登录(签名 cookie `sid`)。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/login` | body `{username, password}`,成功下发 cookie |
| POST | `/api/logout` | 注销 |
| GET  | `/api/formats` | 返回 `{ formats: [...], default }` |
| POST | `/api/validate` | body `{url}` → `{supported, title?, uploader?, duration?, reason?}` |
| POST | `/api/tasks` | body `{url, format?}` → `{taskId}`;忙碌返回 409;非法格式/URL 返回 400 |
| GET  | `/api/tasks/current` | 当前/最近任务状态(未登录返回 401) |
| GET  | `/api/cloud/files` | `{targetDir, files: [{name,size,date,isDir}]}` |
| POST | `/api/cloud/delete` | body `{name}`,删除目标目录下文件;非法名返回 400 |
| GET  | `/api/cloud/download?name=` | 从网盘拉取该文件并作为附件流式下载 |
| WS   | `/ws` | 推送进度事件 `{taskId, stage, percent, title?, message, status}` |

进度 `stage` ∈ `resolving | downloading | uploading | cleaning | done | error`。

## 9. 运维:更新、日志、数据

```bash
# 更新代码后重建并重启
git pull
docker compose build && docker compose up -d

# 查看日志
docker compose logs -f

# 停止 / 删除容器(数据在挂载卷里,不丢)
docker compose down
```

- **临时文件**:`data/tmp` 里的下载/转码文件在任务成功或失败后会清理;偶有遗留的空目录可定期清理。
- **百度登录态**:`data/baidupcs` 持久化,重启无需重新登录(config 里的 BDUSS/STOKEN 仍是权威来源)。

## 10. 常见问题排查

| 现象 | 原因 / 解决 |
|------|------------|
| 启动即退出:`Missing required binaries` | `yt-dlp`/`ffmpeg`/`BaiduPCS-Go` 不在 PATH 或路径错;检查 `paths.*` 与 `cloud.baidu.binary` |
| 启动即退出:`Missing required config` | `config.yaml` 缺字段,对照 `config.example.yaml` 补齐 |
| 上传:`代码: -6, 消息: 请重新登录` | 缺 STOKEN 或凭证过期;补/更新 `stoken` |
| 上传:`代码: -9, 消息: 文件不存在` | 目标目录不存在;程序会自动 mkdir,若仍失败手动在网盘建目录 |
| 页面显示「上传结果未知」 | BaiduPCS-Go 输出无法判定;查看日志确认;凭证或网络问题居多 |
| 大文件上传卡住/极慢 | 网络到百度不稳定(容器 VM 尤甚);小文件可正常上传,换稳定网络或耐心等待 |
| YouTube:`No supported JavaScript runtime` | 需 `deno`;容器已内置,本地部署需安装 deno |
| 校验一直转圈 | yt-dlp 探测较慢或该链接需要登录/地区限制;换链接或稍等 |
| 云盘目录卡片空白 | 首次加载需登录+列目录(几秒);稍等或点「刷新」 |

## 11. 安全建议

- 本服务默认面向**本地单用户**,鉴权为简单账号密码 + 签名 cookie。
- **务必修改** `sessionSecret` 与 `auth.password`(不要保留 `change-me`)。
- `config.yaml`(含 BDUSS/STOKEN)与 `data/` 已在 `.gitignore`,**切勿提交或分享**。
- BDUSS/STOKEN 等同账号凭证,泄漏后请在百度重新登录使旧凭证失效。
- 如需暴露公网:自行加 HTTPS 反代、更强鉴权、CSRF 防护、限流等。
